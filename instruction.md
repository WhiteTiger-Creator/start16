A failed storage migration truncated the authoritative checkpoint registry at `/app/data/checkpoint_registry.json`, and the resume planner at `/app/workflow/plan_resume.go` chooses a restart point under draft rules the training governance board later reversed. The pre-migration snapshot at `/app/data/registry_snapshot_pre_migration.json` and the journal of the changes the migrator posted after it at `/app/data/registry_journal.json` survive beside the truncated file. The end state is that `/app/data/checkpoint_registry.json` holds the registry those two determine between them, in place of what is there rather than beside it, where how they combine, what an invalidation does, what a later reinstatement brings back and what order the result comes out in are decisions the training governance board settled and recorded in the run log at `/app/incident/training_governance_log.md`. Nothing the planner proposes means anything against any other registry, and a run reads that file rather than rebuilding it; whatever writes it is yours to keep or throw away, since only the registry it leaves behind is read.

`/app/workflow/plan_resume.go` is a Go program, built with the toolchain installed here and staying a single `package main` in that one file, whose behaviour matches the board's final decisions. It carries `--input` and `--output-dir` with the defaults it already documents; the shard catalogue, the data incident record and the resume policy always come from their fixed absolute paths under `/app/data`, and `--input` selects the registry alone. `/app/docs/resume_contract.json` is the output contract: paths, schemas, required-field lists, container shapes and sort orders. It says nothing about how any value is derived; that is settled in the same run log, which is mostly routine run notes and where the later dated decision governs.

A run is correct when all of this holds of it. It finishes inside the contract's 90-second budget. `summary.json`, `resume_plan.json` and `refetch_queue.jsonl` are the only files in the directory it wrote into afterwards -- `/app/output` where `--output-dir` is not given -- whatever that directory held beforehand, cleared contents only, with the directory itself still at the path it was given, since the run does not own it; a directory `--output-dir` names but that does not yet exist is created rather than treated as a failure. That end state is a precondition of a successful run rather than a best effort: where something in the directory cannot be cleared, the offending path is named on standard error and the run exits non-zero WITHOUT writing its artifacts, since three files standing beside content the run could not remove is not the output the contract names, and a run that returned success over such a directory would be reporting an end state it did not reach. A run that meets the contract exits nought. Every value is derived from the operational inputs, the same registry yields the same three artifacts on every run, and an alternate registry yields that registry's own answer. The snapshot, the journal, the shard catalogue, the data incident record, the resume policy, the run log and `/app/docs/resume_contract.json` are read rather than written and come back byte for byte unchanged, as does the frozen `/app/workflow/.plan_resume.original.go`; the registry is the one file under `/app/data` that is replaced.
